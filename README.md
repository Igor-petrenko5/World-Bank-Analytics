# World Bank Analytics

**Автоматизированная система мониторинга и анализа социально-экономического развития стран мира на основе World Bank Open Data API**

Учебный дипломный проект: сбор данных Всемирного банка, проверка качества, хранение истории изменений в PostgreSQL, статистический анализ, запуск задач по расписанию с Apache Airflow и визуализация в локальном Yandex DataLens (Open Source).

> **Статус:** ETL и аналитический DAG успешно запущены на локальном стенде; 11 из 11 задач выполнены, 22 теста пройдены. DataLens-дашборд создан локально. Скриншоты и экспорт настроек DataLens пока не размещены в этом репозитории.

## 1. Цель и задачи

Цель — разработать воспроизводимый процесс мониторинга экономических и социальных показателей разных стран и групп стран. Задачи: получение данных через API, контроль их качества, загрузка в реляционное хранилище, расчёт статистических показателей, автоматизация ETL и создание интерактивного дашборда.

Источник: [World Bank Open Data API v2](https://api.worldbank.org/v2). Конфигурация **20 индикаторов** хранится в [config/indicators.json](config/indicators.json): ВВП, темпы роста ВВП, ВВП на душу населения, инфляция, экспорт и импорт, безработица, население, продолжительность жизни, расходы на здравоохранение и образование, использование интернета и другие показатели.

**Периоды различаются:** сбор охватывает **2000–2025**, а сравнительный анализ групп, тренды и панельная регрессия рассчитаны в основном за **2000–2023** из-за неполноты более свежих наблюдений. Корреляционный модуль дополнительно обрабатывает доступные годы до 2025 включительно.

## 2. Архитектура

```text
World Bank Open Data API
          |
          v
Python (collect_all.py, src/api/)
          |
          v
Проверки качества (src/processing/quality.py)
          |
          v
data/processed/<run_id>/*.csv
          |
          v
PostgreSQL 16
  warehouse: измерения, факты, история
  monitoring: статусы ETL, проверки
  marts: аналитические SQL-представления
          |
          +--> Python (корреляции, bootstrap, регрессия,
          |            сравнение групп, тренды) --> CSV
          |
          +--> Yandex DataLens (дашборд)
          
Apache Airflow 3 (Docker) координирует сбор, проверки,
загрузку, проверку витрин и статистические задачи.
```

В качестве инструментов используются Python 3.12, Pandas, NumPy, SciPy, Statsmodels/Linearmodels, SQLAlchemy, PostgreSQL 16, Apache Airflow 3.4, Docker Compose и Yandex DataLens Open Source.

## 4. Структура PostgreSQL

- **warehouse** — `dim_countries`, `dim_indicators`, `dim_years`, `fact_indicators`, `fact_indicator_history`.
- **monitoring** — `etl_runs` и `quality_checks` для истории запусков и контроля качества.
- **marts** — `vw_country_ranking`, `vw_gdp_dynamics`, `vw_gdp_growth`, `vw_gdp_per_capita`, `vw_macro_indicators`.

Главная витрина `marts.vw_macro_indicators` содержит строки «страна × год» с экономическими и социальными показателями. В рейтинге `vw_country_ranking` используются оконные функции `RANK()` и `DENSE_RANK()` с отдельной нумерацией по каждому году.

По результатам локальной загрузки: **217 стран и экономик**, **112 840 записей** в таблице фактов, **5 642 строк** в основной макровитрине (217 × 26). Пропущенные значения отдельных индикаторов допускаются и учитываются в оценке полноты данных.

## 5. Локальный запуск на Windows

### Требования

- Windows, PowerShell и Docker Desktop с работающим Linux Engine;
- Python 3.12, Git;
- доступ к интернету для World Bank API и Docker-образов;
- достаточно памяти для PostgreSQL, Airflow и отдельно развёрнутого DataLens.

В PowerShell из каталога клонированного проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Создайте файл `.env` в корне репозитория. **Внимание:** текущий `.env.example` содержит старые имена `DATABASE_*`, но действующий код и Docker Compose используют `POSTGRES_*`. Для текущей версии необходимы следующие ключи:

```dotenv
POSTGRES_DB=world_bank
POSTGRES_USER=wb_user
POSTGRES_PASSWORD=YOUR_STRONG_LOCAL_PASSWORD
POSTGRES_HOST=127.0.0.1
POSTGRES_PORT=5433
```

Замените пример пароля собственным. **Не публикуйте `.env` и настоящие пароли.** При запуске внутри контейнера Airflow `POSTGRES_HOST=postgres`, `POSTGRES_PORT=5432` задаются самим Compose.

Запуск базового PostgreSQL:

```powershell
docker compose up -d postgres
python -m src.database.connection
```

Для **новой пустой базы** создайте структуру:

```powershell
Get-Content .\sql\01_create_schema.sql | docker compose exec -T postgres psql -U wb_user -d world_bank
```

**Важное ограничение:** `sql/02_create_marts.sql` — экспорт `pg_dump`, который содержит повторное `CREATE SCHEMA marts`. Если `01_create_schema.sql` уже создал схему, в новой базе необходимо убрать повторное создание схемы из копии SQL-экспорта перед применением. В существующей базе с уже настроенными витринами повторно запускать SQL-файл не нужно. Эта часть развёртывания пока не оформлена как полностью идемпотентная миграция.

Ручной сбор и загрузка (после создания таблиц):

```powershell
python collect_all.py
python load_database.py
```

Загрузчик выбирает последний подготовленный набор `data/processed/<run_id>`, либо набор, указанный переменной `WB_DATA_DIR`. Для чистого развёртывания аналитические витрины должны быть созданы **после** установки схемы и до запуска аналитических модулей.

Запуск аналитики:

```powershell
python -m src.analysis.correlation
python -m src.analysis.bootstrap
python -m src.analysis.regression
python -m src.analysis.group_analysis
python -m src.analysis.trends
```

### Запуск Airflow

```powershell
docker compose -f docker-compose.yml -f docker-compose.airflow.yml build airflow
docker compose -f docker-compose.yml -f docker-compose.airflow.yml up -d
docker compose -f docker-compose.yml -f docker-compose.airflow.yml ps
```

Интерфейс: **http://localhost:8080**. В локальной учебной конфигурации используется режим `standalone` и `LocalExecutor`; это **не производственное развёртывание**. DAG: `world_bank_pipeline`. Для первого ручного запуска включите DAG и используйте **Trigger DAG**. Пароль локального администратора Airflow не следует публиковать или добавлять в README.

### Остановка без удаления данных

```powershell
docker compose -f docker-compose.yml -f docker-compose.airflow.yml stop
```

Не используйте `docker compose down -v` или `docker volume prune`, если нужно сохранить содержимое PostgreSQL.

## 6. DAG и автоматизация

`world_bank_pipeline` выполняет **11 задач**:

1. `collect_data` — сбор из API;
2. `validate_data` — проверка подготовленного набора;
3. `load_database` — загрузка в PostgreSQL;
4. `check_marts` — проверка пяти существующих SQL-витрин (не их пересоздание);
5. `run_correlation` — корреляционный анализ;
6. `run_bootstrap` — кластерный bootstrap;
7. `run_regression` — панельная регрессия;
8. `run_group_analysis` — сравнение групп доходов и регионов;
9. `run_trends` — временные тренды;
10. `verify_reports` — наличие и непустота 12 CSV;
11. `finish` — фиксация успешного завершения в логах.

После проверки витрин пять аналитических задач выполняются независимыми ветвями. В DAG предусмотрены три повторные попытки, интервал 5 минут, ограничение параллелизма и запрет одновременных запусков одного DAG. Расписание в исходном коде: **каждый понедельник в 06:00 UTC** (`0 6 * * 1`); `catchup=False`. DAG создаётся приостановленным.

В локальной проверке успешно завершились **11 из 11 задач**, а `monitoring.etl_runs` зафиксировал успешную загрузку 112 840 строк. Показатели актуальны для проведённой проверки, не являются гарантией будущих запусков.

## 7. Контроль качества и тестирование

На этапах сбора и загрузки проверяются обязательные поля и ключи, отсутствие дубликатов «страна–индикатор–год», ожидаемые коды индикаторов и годы, числовые значения, допустимость пропусков и полнота данных. Отчёты сохраняются в CSV и в таблице `monitoring.quality_checks`.

Запуск тестов:

```powershell
python -m pytest tests -v
```

На локальном стенде **22 теста прошли успешно**: API, контроль качества, bootstrap и регрессионные функции. Новые версии проекта следует проверять повторно.

## 8. Статистический анализ и результаты

Модули выполняют корреляции Пирсона/Спирмена, анализ первых разностей, bootstrap с повторной выборкой стран целыми кластерами, панельные регрессии с фиксированными эффектами стран и годов, сравнения четырёх групп доходов, семи регионов и временных трендов.

Отчёты расположены в `reports/statistics/`, включая `correlations_by_year.csv`, `correlations_first_differences.csv`, `cluster_bootstrap.csv`, `regression_results.csv`, `income_group_statistics.csv`, `region_statistics.csv`, `group_correlations.csv`, `income_group_trends.csv`, `region_trends.csv`, `global_trends.csv` и `long_term_changes.csv`.

**Примеры фактических результатов (2000 → 2023):**

| Группа доходов | Прирост среднего номинального ВВП на душу населения | Изменение средней продолжительности жизни |
|---|---:|---:|
| High income | +156,37% | +4,41 года |
| Upper middle income | +231,19% | +4,91 года |
| Lower middle income | +171,70% | +8,18 года |
| Low income | +136,86% | +11,65 года |

Это **невзвешенные средние по странам с доступными наблюдениями**. Число наблюдений между годами может отличаться; прирост номинального ВВП в текущих долларах не равен реальному экономическому росту.

Панельные модели (2000–2023) выявили отрицательную условную связь между безработицей и ростом ВВП, а также положительную связь логарифма ВВП на душу населения с продолжительностью жизни. Связь доли расходов на здравоохранение в ВВП с продолжительностью жизни в используемой спецификации не достигла уровня значимости 5% (`p≈0,092`). Результаты **не доказывают причинно-следственные связи**. Сопоставимость стран ограничена составом данных, пропусками и применяемой классификацией доходов.

## 9. DataLens

В локальном **Yandex DataLens Open Source** создан интерактивный дашборд «Мировая экономика» с графиками ВВП, роста ВВП, инфляции, безработицы, продолжительности жизни, сравнения групп доходов и использования интернета. Основной источник — `marts.vw_macro_indicators`, рейтинг ВВП — `marts.vw_country_ranking`. Настроены селекторы года, страны и группы доходов.

DataLens установлен **в отдельной папке/отдельном Docker Compose** и не является частью данного Git-репозитория. На локальном компьютере интерфейс использует **http://localhost:8081**. Этот адрес недоступен внешним посетителям GitHub; для воспроизводимости визуализации следует отдельно приложить скриншоты или экспорт конфигурации. Для подключения к PostgreSQL использовался пользователь с правами только на чтение витрин и Docker-сеть DataLens.

## 10. Ограничения и дальнейшая работа

- `.env.example` содержит старые имена переменных: при запуске использовать `POSTGRES_*` из раздела 5.
- Экспорт `sql/02_create_marts.sql` требует подготовки при чистом развёртывании, так как содержит `CREATE SCHEMA marts`; обычные SQL-витрины автоматически отражают обновлённые факты.
- Настройка Airflow предназначена для локального учебного стенда: учётные данные метаданных в Compose демонстрационные и перед промышленным развёртыванием должны быть заменены.
- Полнота данных различается по индикаторам и годам; результаты анализа нельзя автоматически интерпретировать как причинные эффекты.
- Исходный код и CSV публикуются в репозитории; локальная база данных, её том Docker и конфигурация самого DataLens не переносятся через `git clone`.
- Дальнейшие шаги: оформить воспроизводимую SQL-миграцию, обновить шаблон `.env.example`, приложить скриншоты Airflow и DataLens и подготовить итоговый отчёт для защиты.
